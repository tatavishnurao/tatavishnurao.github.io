# tailbench — evidence and limits

The portfolio story is pinned to [ec3306c, 22 October 2026](https://github.com/tatavishnurao/tailbench/commit/ec3306c), not current HEAD. The architecture shows two different comparisons: tailbench's internal statistical verdict and an audit of tool output against phantom's logs.

## Findings worth keeping separate

- **Coordinated omission:** in tailbench's paused-clock synthetic test, a 500 ms stall produces closed-loop p99 around 1 ms versus open-loop p99 around 401 ms. These are HdrHistogram readings from a simulated clock, not new wall-clock measurements or real-model results. [Snapshot README table and test command](https://github.com/tatavishnurao/tailbench/blob/ec3306c/README.md#the-problem); [test implementation](https://github.com/tatavishnurao/tailbench/blob/ec3306c/tests/stall.rs). The separate [loopback audit](https://github.com/tatavishnurao/tailbench/blob/ec3306c/phantom/docs/audits/tailbench.md) uses real HTTP and a different scenario; do not substitute one table for the other.
- **Provenance before traffic:** `run` writes and flushes the manifest before starting the schedule. A write/flush error returns without sending requests. The manifest records build/runtime git provenance, CPU and runtime information, using UNKNOWN where unavailable. [Implementation](https://github.com/tatavishnurao/tailbench/blob/ec3306c/src/lib.rs); [manifest](https://github.com/tatavishnurao/tailbench/blob/ec3306c/src/manifest.rs).
- **Calibration, not a guarantee:** synthetic lognormal bodies, correlated samples, per-run offsets and scripted stalls exposed elevated false-direction rates for the hierarchical pooled-percentile bootstrap. That motivated per-run Welch as the default. It estimates the mean of per-run percentiles, not a pooled percentile. Limited power and synthetic-only calibration still apply. [Calibration setup, summary and power tables](https://github.com/tatavishnurao/tailbench/blob/ec3306c/docs/calibration.md); [comparison implementation](https://github.com/tatavishnurao/tailbench/blob/ec3306c/src/compare.rs). Refusal checks reject empty or closed-loop/mixed-runner inputs; they are not a promise that every provenance mismatch is automatically rejected.
- **Body versus episodes:** split comparison estimates normal-request latency using samples sent outside episode windows, separately from episode frequency per exposure time. It can exclude fast requests inside those windows, and the threshold can classify a slow body mode as episodes. [Split calibration and caveats](https://github.com/tatavishnurao/tailbench/blob/ec3306c/docs/calibration.md#split-verdict).
- **Different quantities can both be correct:** GuideLLM 0.8.1 reports per-request mean ITL (weighted by gap count), whereas vLLM bench serve 0.32.0 pools individual inter-message gaps. In the synthetic streaming scenarios, averaging a request's gaps and measuring the worst gap answer different questions. Percentile conventions differ too. [Definitions](https://github.com/tatavishnurao/tailbench/blob/ec3306c/phantom/docs/audits/README.md#oha-guidellm-and-vllm-compared); [GuideLLM report, G2/G3](https://github.com/tatavishnurao/tailbench/blob/ec3306c/phantom/docs/audits/guidellm.md); [vLLM report](https://github.com/tatavishnurao/tailbench/blob/ec3306c/phantom/docs/audits/vllm.md).
- **Intended start is not actual send:** vLLM bench serve 0.32.0 starts TTFT after its concurrency-slot wait and reports `client_queue_time` separately. Scenario V5 compares each request's TTFT plus its own queue time with intended-schedule truth; adding marginal percentiles is not the same operation. [V5 report and source read](https://github.com/tatavishnurao/tailbench/blob/ec3306c/phantom/docs/audits/vllm.md#results). [oha 1.16.0](https://github.com/tatavishnurao/tailbench/blob/ec3306c/phantom/docs/audits/oha.md) also illustrates why connection limits, latency correction and percentile indexing must be specified.

All external-tool audit observations above are scripted workloads over loopback on one Intel i7-14650HX laptop under WSL2, not real-model serving performance. Reported min–max ranges are observations, not guaranteed bounds. Server timestamps stop at handler/response-stream hand-off, omitting downstream socket delivery and client read overhead. Seeded scripts can be deterministic while measured wall-clock timings vary. See [phantom's truth-log limits](https://github.com/tatavishnurao/tailbench/blob/ec3306c/phantom/docs/truth-log.md#limits). This project is unrelated to [MIT's TailBench](https://tailbench.csail.mit.edu/).

## Historical totals and counting rules

- **11,584 physical Rust lines** across tracked `src/**/*.rs`, `tests/**/*.rs`, `phantom/src/**/*.rs` and `phantom/tests/**/*.rs`: includes blank lines, comments, test code and the shared test helper, counted once. Excludes the root `build.rs` (122 lines). All tracked `.rs` files including that build script total **11,706**, so this is not a production-code-only count.
- **138 passed, 21 ignored, zero failed** when `cargo test --workspace` was actually run on 25 October 2026 against a detached checkout of this snapshot during the portfolio verification. Sum Cargo's per-target test-result counts; doc-test targets contributed zero. Ignored tests were not run. The 21 comprise 17 phantom tool-audit scenarios, three library statistical/calibration tests, and one slow synthetic comparison integration test. Calling all 21 “machine-dependent audit tests” is misleading. Cargo may count provenance tests that return early as passed; see the README's skip caveat.
- **Four audited tools**, including tailbench itself: [audit index](https://github.com/tatavishnurao/tailbench/tree/ec3306c/phantom/docs/audits). This counts report subjects, not four independent verification systems. External-tool audits were not re-run for this portfolio update.
- **62 reachable commits** through this snapshot, including the initial commit. `git rev-list --count ec3306c` gives 62; their recorded author/committer dates span 16–22 October 2026. This is repository history, not hours worked or a current-HEAD count. [History](https://github.com/tatavishnurao/tailbench/commits/ec3306c/).
- **v0.1.0 is a real annotated tag**, dated 20 October 2026, pointing to `d93215d`, earlier than the story snapshot. A tag is not proof of a GitHub Release or registry publication. [Tag](https://github.com/tatavishnurao/tailbench/tree/v0.1.0).

The totals describe only this historical snapshot; they are not current-HEAD statistics.

## Publication and roadmap reconciliation

Current source inspected separately: [77d83b8](https://github.com/tatavishnurao/tailbench/tree/77d83b8).

- Registry evidence confirms [tailbench 0.1.0](https://crates.io/crates/tailbench/0.1.0) and [tailbench-phantom 0.2.1](https://crates.io/crates/tailbench-phantom/0.2.1) are published. The registry records publication on 22 and 24 October 2026 respectively. The README's “nothing is published” sentence is stale.
- [Cargo workspace](https://github.com/tatavishnurao/tailbench/blob/77d83b8/Cargo.toml) defines tailbench as a library; the caller supplies an async closure. No tailbench CLI or bundled HTTP target is implied.
- [phantom's Cargo manifest](https://github.com/tatavishnurao/tailbench/blob/77d83b8/phantom/Cargo.toml) defines the `phantom` binary, and its [CLI implementation](https://github.com/tatavishnurao/tailbench/blob/77d83b8/phantom/src/main.rs) includes serving, demo and report commands. “No CLI” is true of the harness, not the whole workspace.
- phantom and the four audit adapters already exist in implementation and reports. Listing those as future roadmap work is stale. A tailbench harness CLI remains future work.
